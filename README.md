# Task Management API

Небольшой учебный REST API на Python 3.12+, FastAPI, PostgreSQL, SQLAlchemy 2.0 async и Pydantic v2. Redis опционально кеширует страницы списка задач на 30 секунд по умолчанию.

## Структура

```text
app/api/          HTTP-маршруты и зависимости FastAPI
app/schemas/      Проверка входных данных и формат ответов
app/services/     Бизнес-логика и кеширование
app/repositories/ SQL-запросы к задачам
app/models/       SQLAlchemy-модели
app/database/     Асинхронная сессия PostgreSQL
app/core/         Настройки и JSON-логирование
app/tests/        Простые API-тесты без запущенных PostgreSQL и Redis
alembic/          Миграции схемы БД
```

## Локальный запуск без Docker

1. Установите Python 3.12 или новее, PostgreSQL и при желании Redis. Создайте пустую БД и пользователя PostgreSQL с правами на создание таблиц.
2. В каталоге проекта создайте окружение и установите зависимости:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. Скопируйте `.env.example` в `.env`. Замените `replace_me` в `DATABASE_URL` на локальный пароль. Если Redis не запущен, задайте `REDIS_URL=`.
4. Примените миграцию и запустите API:

   ```bash
   alembic upgrade head
   uvicorn app.main:app --reload
   ```

Откройте `http://127.0.0.1:8000/docs` для Swagger UI. `GET /health` сообщает только, что приложение отвечает; он не проверяет готовность PostgreSQL и Redis.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения вида `postgresql+asyncpg://user:password@localhost:5432/dbname` |
| `REDIS_URL` | `redis://localhost:6379/0`; пустое значение отключает кеш |
| `CACHE_TTL_SECONDS` | Время жизни кеша списка в секундах; по умолчанию 30 |
| `LOG_LEVEL` | Уровень JSON-логов; по умолчанию `INFO` |

Не храните настоящий `.env` в системе контроля версий.

## API

| Метод | Путь | Успех | Описание |
| --- | --- | --- | --- |
| `POST` | `/api/v1/tasks` | `201` | Создать задачу |
| `GET` | `/api/v1/tasks` | `200` | Список; `offset` от 0 и `limit` от 1 до 100 |
| `GET` | `/api/v1/tasks/{task_id}` | `200` | Получить задачу |
| `PATCH` | `/api/v1/tasks/{task_id}` | `200` | Частично обновить задачу |
| `DELETE` | `/api/v1/tasks/{task_id}` | `204` | Удалить задачу |
| `GET` | `/health` | `200` | Проверка ответа приложения |

Поля задачи: `title` (обязательно, 1–200 символов), `description` (до 2000 символов или `null`), `status` (`todo`, `in_progress`, `done`). Создание по умолчанию задаёт статус `todo`. В ответе также есть `id`, `created_at`, `updated_at`.

Пример:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Настроить мониторинг","status":"todo"}'
```

Некорректные данные возвращают `422`, отсутствующая задача — `404`, неожиданная ошибка — `500` с безопасным общим сообщением. Запросы логируются в JSON с `X-Request-ID`, HTTP-методом, путём, кодом ответа и длительностью. Если Redis недоступен, API читает список из PostgreSQL и пишет предупреждение в лог.

## Тесты

```bash
pytest -q
```

Тесты подменяют репозиторий памятью и проверяют маршруты, статус-коды и валидацию. Для реальной работы API нужны запущенный PostgreSQL и применённая миграция.

## Что настроить самостоятельно для практики DevOps

- Управление PostgreSQL и Redis, их учётными данными и сетевым доступом.
- Сборку образа и контейнерный запуск, если захотите контейнеризировать проект.
- CI/CD, запуск миграций при выпуске и стратегию отката.
- Прокси, TLS, домен и настройки Linux-сервера.
- Мониторинг, сбор логов, резервное копирование и восстановление БД.
